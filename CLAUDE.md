# HiTaqnia / Haykal application

This is a HiTaqnia Laravel project built on the **Haykal** framework (`hitaqnia/haykal`) with **Huwiya** authentication. Generic Laravel 13 / Filament 5 / PHPUnit 12 guidance lives below in the `<laravel-boost-guidelines>` block. HiTaqnia-specific conventions live in `.claude/skills/haykal-*/SKILL.md` and are auto-loaded by Claude Code on demand.

**Always start non-trivial work by consulting `haykal-overview`** — it is the index for the rest of the skills. The skill set:

**Hard rules**
- PHP 8.3+, `declare(strict_types=1)` at the top of every new file under `domain/`, `support/`, `app/Apis/`, `app/Panels/`.
- ULIDs everywhere — `HasUlids` on every model, `$table->ulid('id')->primary()` and `$table->foreignUlid(...)` in migrations.
- Three locales required for any user-facing string: `en`, `ar`, `ku`.
- Recoverable business failures return `Result::failure(<DomainErrors>::name())` — no exceptions for known outcomes. Infrastructure / programmer errors throw.
- API endpoints **always** return through `ApiResponse::ok|created|paginated|noContent|validationError|businessError|...`. The Haykal envelope is non-negotiable.
- Filament panels extend `HiTaqnia\Haykal\Filament\BasePanel`; resources extend `HiTaqnia\Haykal\Filament\Resources\BaseResource`; API modules extend `HiTaqnia\Haykal\Api\ApiProvider`. Don't reach for vanilla base classes.
- Auth is Huwiya OAuth2 → JWT. Default `web` guard is `huwiya-web`; default `api` guard is `huwiya-api`. Don't add Sanctum-style auth without team agreement.
- Domain models live under `domain/<Context>/Models/<Entity>.php`, never in `app/Models/`. The starter only ships `Domain\Identity\Models\{User,Role,Permission}`.

The `<laravel-boost-guidelines>` block below covers generic Laravel/Filament/PHPUnit/Pint conventions and is regenerated by `php artisan boost:install` — don't hand-edit it. The `haykal-*` skills override it where HiTaqnia conventions differ.
